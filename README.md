# Harness Visualizer

Understand and control LLM agent harnesses without reading every line of their code and
prompts. The tool statically extracts a typed **Harness IR** from TypeScript source,
reconciles it with recorded **execution traces**, and renders an interactive visualizer that
keeps these apart:

* **deterministic control** vs **model discretion** (who decides each branch),
* what the model may **request** vs what code **authorizes** and **executes**,
* **enforced** code checks vs **advisory** prompt instructions,
* **state and memory** that enters each model call,
* **observed** runtime behavior vs **static** possibility,
* what remains **unknown**.

Every claim carries an evidence label — `static`, `inferred` (heuristic: verify), `runtime`,
or `unknown` — and a link to its source.

**Live demo:** https://kt3k.github.io/harness-visualizer/ (built and deployed by GitHub
Actions from `main`). All sample harnesses are **synthetic fixtures** written for this
project.

## Quick start

Requirements: Node.js ≥ 20.

```bash
npm ci
```

```bash
npm run dev
```

Opens the visualizer on http://localhost:5173 with the bundled samples (`dev` first analyses
every harness under `fixtures/harnesses/` into `web/public/data/`).

Production build (static site in `dist/`):

```bash
npm run build && npm run preview
```

## Analyse a harness

A harness directory needs a `harness.json`:

```json
{ "id": "my-agent", "name": "My agent", "synthetic": false, "include": ["src/**/*.ts", "prompts/*.md"] }
```

```bash
npx tsx src/cli.ts analyze path/to/my-agent --out my-agent.ir.json
```

(`node bin/harness-viz.mjs …` is equivalent.) Options: `--redaction strict|standard`
(default `standard`), `--cache .cache/ir` for incremental re-analysis. The analyzer only
parses files; it never imports or runs harness code. To show your harness in the UI, put its
directory (with optional `traces/*.jsonl`) under `fixtures/harnesses/` or pass another root:
`npx tsx scripts/build-site-data.ts <harnesses-root> web/public/data`.

Supported out of the box: Anthropic and OpenAI SDK calls (direct or through a wrapper),
`fs`, `child_process`, `fetch`, Stripe refunds/charges, nodemailer, `pg`, readline prompts.
Extend [`src/analyzer/catalog.ts`](src/analyzer/catalog.ts) for other SDKs; uncatalogued
calls are reported as `Unknown`, never dropped.

## Inspect

| View | Answers |
|---|---|
| **A Architecture** | agents, subagents, tools, stores, entry points; findings |
| **B Decision boundary** | where the model chooses; request → authorization → execution |
| **C Effects & authority** | reachable side effects and their gates; prompt-only rules |
| **D State & memory** | what enters each model call; stores, writers, readers |
| **E Execution trace** | replay recorded runs on the graph (no re-execution); spec-vs-run reconciliation |
| **F Change impact** | potential direct/indirect impact of a prompt, guard or `file:line`; IR diff and before/after behavior between versions |
| **G Unknowns & coverage** | unresolved items, gaps, inferred claims, metrics |

Click a node for its purpose, decision authority, inputs/outputs, gates, reachable effects,
source (built-in viewer + GitHub link), evidence and uncertainties. Double-click / Enter
expands containers. Keyboard: Alt+A…G views, arrows move, +/− zoom, `/` search, `?` legend.


## Export

In the UI: **Export → IR (JSON) / Summary (Markdown) / Reconciliation report**, with
`standard` (mask secrets, e-mails, phone numbers) or `strict` (also withhold prompt bodies and
trace summaries) redaction. The CLI `summary` command produces the same Markdown.

## Traces

Opt-in instrumentation: [`src/instrument/tracer.ts`](src/instrument/tracer.ts) emits the
[trace event schema v1](schema/trace-event.schema.json) (JSONL) with correlation ids,
parent/child spans, node ids or captured source locations, input hashes and redacted output
summaries. It only records; it does not change control flow. Fixture traces are generated by
`npm run gen:traces` (scripted events, nothing executed).

## Test

```bash
npm run typecheck && npm test
```

```bash
npm run eval
```

```bash
npm run build && (npm run preview &) && npm run e2e
```

`npm test` covers all fixtures (schema validity, determinism, expected semantics),
adversarial fixtures (aliasing, eval, unresolvable dispatch, uncatalogued packages, syntax
errors, redaction), reconciliation (mapping, unexplained successions, invariant violations,
retries / cancellation / malformed output / denial / subagents), impact, diff, cache and the
tracer. `eval` measures extraction against hand labels; `e2e` answers the seven operator
questions in the real UI.

## Repository layout

```
src/analyzer/      TypeScript adapter (program index, catalog, analysis, cache)
src/core/          IR types, graph index, reachability, impact, diff, reconcile, redact, summary
```
